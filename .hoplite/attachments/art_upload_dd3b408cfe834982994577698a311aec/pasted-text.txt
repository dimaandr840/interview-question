ПРАВИЛА ПОЛЕЙ
- t — заголовок вопроса дословно, как его гуглят, с вопросительным знаком. Без нумерации,
без «Вопрос:», без названий компаний. Заголовки уникальны в пределах файла (по ним идёт
дедупликация при импорте, и из них автоматически делается slug).
- l — строго одно из: "Junior", "Middle", "Senior".
- c — slug темы из массива categories выше. Каждый использованный c обязан быть в categories.
- g — 3–8 тегов: только латиница, lowercase, kebab-case, только технологии и концепты
(java, collections, jvm, gc, sql, indexes, transactions, big-o, multithreading).
Запрещены теги вида «собеседование», «важно», «вопрос», уровни и названия компаний.
- d — TL;DR: 1–2 предложения, 150–300 символов, БЕЗ html-тегов (идёт в snippet, tldr и
в поисковый сниппет). Самодостаточно отвечает на вопрос.
- pop — true только для действительно частых вопросов, не больше 20% файла. Иначе поле опусти.
- s — секции ответа. Обязательный порядок и заголовки h:
1) "Короткий ответ" — только p
2) "Как это работает подробнее" — p и/или b
3) "Пример кода" — только code (секцию опускай, только если код совсем неприменим)
4) "Что использовать на практике" — b
5) "Подводные камни" — b
6) "Как отвечать на собеседовании" — b, 1 пункт с каркасом ответа через « → »
Дополнительно можно вставить "Сравнение" (b с пунктами вида «X — когда использовать — сложность»).

РАЗМЕТКА
- Внутри строк p и b разрешены только инлайн-теги: <strong>, <em>, <code>, <mark>, <u>, <s>,
<a href="...">. Ничего другого: ни <div>, ни <ul>, ни <br>, ни Markdown (**, `, #, -), ни эмодзи.
- <code> — для идентификаторов, методов, типов, значений сложности.
- <mark> — для главного акцента: ключевой термин, число, подвох. Не больше 2 <mark> на секцию.
- <strong> — для названий подпунктов в начале строки b.
- Внешних ссылок не добавляй, если их не было в исходнике.

КОД
- code.lang — один из: java, kotlin, sql, python, javascript, typescript, bash, json, yaml, go, text.
- code.title — имя файла или короткая подпись.
- code.lines — МАССИВ СТРОК, по одной строке кода на элемент. Никаких "\n" внутри строк.
Двойные кавычки внутри кода экранируй как \" . Код рабочий и минимальный, без «...» и псевдокода.
Отступы делай пробелами прямо в начале строки.
