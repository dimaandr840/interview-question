# Задание: генерация вопросов для Frontend Developer (qareerquest.com)

Ты — опытный интервьюер и практикующий frontend-эксперт с 10+ годами опыта.
Ты сгенерируешь порцию вопросов для базы `qareerquest.com` в строго заданном формате.

## Куда писать

Файл — **JSONL**: одна строка = один JSON-объект вопроса, без переносов строк внутри.
Пиши через `shell` так (пиши партиями по 8–12 строк, чтобы не терять результат):

```bash
cat > questions/.chunks/ИМЯ.jsonl <<'EOF'
{"t":"...","l":"Junior","c":"...","g":["..."],"d":"...","s":[...]}
{"t":"...","l":"Middle",...}
EOF
# следующие партии:
cat >> questions/.chunks/ИМЯ.jsonl <<'EOF'
...
EOF
```

Никаких пояснений в файле. В конце проверь себя:
`node -e "const fs=require('fs');const l=fs.readFileSync('questions/.chunks/ИМЯ.jsonl','utf8').split('\n').filter(Boolean);console.log(l.length);l.forEach((x,i)=>{try{JSON.parse(x)}catch(e){console.log('BAD line',i+1,e.message)}})"`

## Схема одного вопроса (ключи строго такие)

```json
{
  "t": "Как работает event loop в JavaScript?",
  "l": "Middle",
  "c": "javascript-core",
  "g": ["javascript", "event-loop", "async", "microtasks"],
  "pop": true,
  "d": "Event loop поочерёдно разбирает стек вызовов, микрозадачи и макрозадачи; микрозадачи (промисы) выполняются до следующей макрозадачи.",
  "s": [
    { "h": "Короткий ответ", "p": ["<code>Event loop</code> — механизм, который выполняет синхронный код, затем все микрозадачи и только потом следующую макрозадачу."] },
    { "h": "Как это работает подробнее", "p": ["Абзац разбора простым языком, 90–160 слов: что происходит под капотом, почему так устроено, что важно в реальной практике."], "b": ["<strong>Микрозадачи:</strong> промисы, <code>queueMicrotask</code> и <code>MutationObserver</code>."] },
    { "h": "Пример кода", "code": { "lang": "javascript", "title": "event-loop.js", "lines": ["console.log(\"start\");", "setTimeout(() => console.log(\"timeout\"), 0);", "Promise.resolve().then(() => console.log(\"promise\"));", "console.log(\"end\");"] } },
    { "h": "Что использовать на практике", "b": ["Разбивайте длинные синхронные блоки, чтобы не блокировать отрисовку и микрозадачи."] },
    { "h": "Подводные камни", "b": ["<mark>Долгая микрозадача</mark> может заморозить страницу, потому что очередь микрозадач опустошается целиком до рендера."] },
    { "h": "Как отвечать на собеседовании", "b": ["Стек → микрозадачи → макрозадачи → пример порядка вывода → практический вывод."] }
  ]
}
```

## Правила полей

- `t` — заголовок вопроса дословно так, как гуглят; заканчивается на `?`. Без нумерации, без «Вопрос:», без названий компаний. **Уникален во всём файле.**
- `l` — строго `"Junior"` | `"Middle"` | `"Senior"`. Senior-вопрос обязан содержать компромисс/trade-off и не иметь единственно верного ответа.
- `c` — slug категории, выданный тебе в задании (одинаковый для всего твоего файла).
- `g` — 3–8 тегов: только латиница, lowercase, kebab-case, только технологии и концепты. Запрещены теги «собеседование», «важно», «вопрос», уровни (`junior`/`middle`/`senior`), названия компаний.
- `d` — TL;DR, **150–300 символов**, 1–2 предложения, **без HTML-тегов**, самодостаточно отвечает на вопрос.
- `pop` — `true` только для реально частых вопросов; примерно у 15% вопросов. Опускай поле у остальных.
- `s` — секции строго в порядке: `Короткий ответ` (только `p`, 1 пункт), `Как это работает подробнее` (`p` и/или `b`), `Пример кода` (только `code`), `Что использовать на практике` (`b`), `Подводные камни` (`b`), `Как отвечать на собеседовании` (`b`, ровно 1 пункт с каркасом через « → »).

## Разметка

- В строках `p` и `b` допустимы только инлайн-теги: `<strong>`, `<em>`, `<code>`, `<mark>`, `<u>`, `<s>`, `<a href="...">`.
- Запрещены `<div>`, `<ul>`, `<li>`, `<br>`, Markdown (`**`, `` ` ``, `#`, `-`), эмодзи.
- `<code>` — для идентификаторов, методов, типов, значений сложности.
- `<mark>` — главный акцент, не больше 2 на секцию.
- `<strong>` — названия подпунктов в начале строк `b`.
- Внешних ссылок не добавляй.

## Код

- `code.lang` — один из: `javascript`, `typescript`, `bash`, `json`, `yaml`, `text` (CSS/HTML без кода давай как `text` или пропускай секцию).
- `code.lines` — массив строк, по одной строке кода на элемент. Никаких `\n` внутри строк. Двойные кавычки внутри кода экранируй как `\"`. Код рабочий и минимальный, без «...» и псевдокода.
- Отступы — пробелами в начале строки.
- Секцию `Пример кода` опускай только для чисто теоретических вопросов.

## Качество

- **Никаких шаблонных, повторяющихся ответов.** Каждый разбор уникален и говорит по делу о конкретной теме вопроса. Запрещены общие фразы-заглушки вроде «Практический подход: зафиксируйте риск…» и одинаковые секции у разных вопросов.
- Вопросы не повторяются и не дублируют друг друга по смыслу ни внутри твоего файла, ни по смыслу с типовыми вопросами соседних тем.
- Формулировки — как их реально задают на собеседованиях.
